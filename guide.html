PDF Delivery Tools

User guide for the Daily Backlog Dashboard and the URL Analysis tool - what to upload, what each screen shows, and how to read the results.

1. Getting started

PDF Delivery Tools is a web page that runs on your own computer. It has four tools, reachable from the sidebar:

Daily Backlog Dashboard

Combine the Reg Transform UI export and the Power BI export, explore the PDF backlog, and produce the daily Excel report.

URL Analysis

Check any list of URLs: is it working, is it a PDF or a page with PDFs, how many pages, what language, when was it last modified.

Base Templates

The team's Base Template sheet inside the tool: search every monitoring template, add new rows, and import the latest sheet from Excel.

Base Template Analysis

Compare a URL analysis file with the Base Templates, joined on domain, and get every row flagged for review.

Start the tool

  1. Open a terminal in the project folder (the one containing run_dashboard.bat).
    First time only: pip install -r requirements.txt
  2. Run .\run_dashboard.bat
  3. Open http://localhost:8080 in your browser. Use the sidebar to switch tools - you do not need to restart anything.
  4. To stop it, press Ctrl+C in the terminal window.
Your work stays when you switch tools. Daily Backlog Dashboard, URL Analysis, Base Templates and Base Template Analysis each keep their results, filters, selections, chosen columns and typed or pasted text while you use another page, and show them again when you come back (also after a refresh). This lasts for as long as that browser tab stays open; closing the tab, or restarting the tool, clears it - the page then tells you that the earlier results are gone. An analysis that was still running keeps running while you are away and carries on showing its progress when you return.
The page is only available on your own computer (127.0.0.1). To use another port, set the PORT environment variable before starting.

2. Daily Backlog Dashboard

Use this each morning to see the PDF book backlog: how many books, which domains and API Results they belong to, and which need action.

Step by step

  1. Open Daily Backlog Dashboard in the sidebar.
  2. Choose the Reg Transform UI Export (.csv) and the Power BI Details Table Export (.xlsx). The file names appear under the boxes.
  3. Click Generate Daily Report. Progress steps appear (loading, matching Book Types, extracting domains, summaries...).
  4. The dashboard appears after about 15-30 seconds. The Excel report keeps building in the background (about a minute for a large CSV); the Download Excel Report button turns green when it is ready. You can already use the dashboard meanwhile.
  5. Review the Data quality panel first (see below), then use the cards, filters and tabs.
Your filters, tab and selected books are remembered. If you open URL Analysis and come back, the dashboard is restored - you do not need to upload the files again. Reset Dashboard clears everything.

Filters and search

  • In the Overview, clicking a domain row or an API Result row applies that filter.

Send books to URL Analysis

Select books and click Analyze Selected URLs. Their source links open in the URL Analysis tool, together with Document ID, title, domain, API Result and Book Type. Blank and duplicate links are dropped (the screen tells you how many).

Base Template Analysis. Click Base Template Analysis in the bar above the table to check the ticked books (or, when none are ticked, every book in the current filters and view) against the Base Templates, and Base Template Analysis - All Filtered at the bottom to check every book in the current filters whatever the view. Each book's Document ID, Domain, Spider Template and URL are sent and the comparison opens already done. Books with no URL are kept, so they are flagged as Missing URL. The row numbers in the report are the books' positions in the backlog report; Back to Daily Backlog Dashboard returns you with the filters and ticks as you left them.

3. URL Analysis

One tool with four ways of giving it URLs (Paste URLs, Excel Batch Upload, From Daily Backlog, Page Source). Whichever you use, every URL is checked in exactly the same way and the results appear in the same dashboard and the same Excel file.

Sites that refuse the tool (HTTP 403, Cloudflare)

Some sites answer a script with HTTP 403 - Access denied but serve the same file to a person in a browser. Tick Open blocked sites in a browser window (under the input box, before you analyze) or, for an analysis that has already run, click Retry blocked (n) in browser window. For each refused URL the tool then opens a real Edge/Chrome window, loads the site like any visitor, and reads the file from inside that page - the same request the site's own pages make.

  • Verification pages: if the site shows a "verify you are human" page, the window is visible and a yellow banner on the dashboard says "A browser window is waiting for you". Approve it in that window yourself; the tool waits (up to 3 minutes) and carries on. The tool never solves or disguises a check, and an approval is remembered for next time (the window uses its own profile in data/browser_profile).
  • Rows read this way carry the note "The site refused the automated request, so the file was read through a real browser window" and show the first answer (403) next to the final one (200). If the site still refuses, the row stays BLOCKED with the reason, and Paste page source remains available.
  • It is slower (one window, one file at a time) and only used for URLs the plain check could not read. It needs Microsoft Edge or Google Chrome on this computer and a desktop session. To run the window hidden (no approval possible), start the tool with the environment variable URL_ANALYZER_BROWSER_HEADLESS=1.

Download PDFs (a new folder, files named by Document ID)

Click Download PDFs above the results table to save the documents themselves. Tick rows first to save only those; with nothing ticked, every analysed row is saved. In the window that opens you can type a folder to work in (leave it empty for the default, output/pdf_downloads); the tool always creates a new folder inside it named like Daily Backlog_2026-10-08_143015 - it never writes into your Downloads folder or an existing folder.

  • Each file is named with its Document ID: DOC123.pdf. Characters Windows does not allow in file names are replaced by _; the same ID twice gives DOC123.pdf and DOC123_2.pdf; a row without an ID is saved as NoDocumentId_Row7.pdf. Word files keep .doc / .docx.
  • What is saved: a direct document, or the single document found on a landing page. Pages with several documents, pages with none, and URLs that do not work are skipped, and download_report.csv in the folder lists every row with its status (Saved / Failed / Skipped), the file name, the size, how it was read, and the reason when it was not saved.
  • The same Open blocked sites in a browser window choice applies (it is ticked in the window when you ticked it above), so a site that refuses scripts is read the same way, and you approve any verification page in the browser window. The same address on several rows is downloaded once and copied for each Document ID. Files up to 200 MB are saved.
  • Skip: while saving, every file being fetched right now is listed with its own Skip button (slow download, or waiting for a verification page you do not want to approve). Skipping ends that file at once, marks it Skipped - Skipped by you in the report, and the saving goes on with the others. During an analysis with the browser option, the yellow "waiting for you" banner has a Skip this URL button too; that row stays BLOCKED with the note.
  • Stop ends the saving; files already written stay. Open folder shows the new folder in the file explorer when it finishes.
Stopping. While URLs are being analysed, Stop analysis (next to the percentage) ends the run: URLs already being checked finish, the rest are skipped, and everything analysed so far stays in the table and can be downloaded or sent on. Re-analyze All checks everything again. In Find PDFs on a Page, the Stop button under the form stops the search for PDFs; once the analysis has started, use Stop analysis.
Up to 5,000 URLs per run. Analysis runs in the background and the table fills as results arrive.

Finding all the PDFs on one page

Use the Find PDFs on a Page tab when you have one address that leads to many PDFs - for example a code of laws with a list of titles, each of which opens into chapters and sections. You give the page address (and, if you want only part of the page, a scope); the tool collects every PDF link, then analyses each one: page count, last modified date, file size, language and whether it works. The results appear in the normal dashboard, and Download Analysis Results / Download Selected give the Excel file, with extra columns Section Path (where the PDF sits in the page's outline, e.g. Title 1: Government > General Provisions > Chapter 1) and Source Page.

  1. Paste the page address, for example https://cnmilaw.gov/commonwealth-code. A #... part at the end is ignored.
  2. Scope (optional) - a CSS selector for the links you want. Example, only the PDFs under the first title:
    #cmctree>.tlist>li:nth-of-type(1) a[data-pdf*='.pdf']
    Leave it empty to take every PDF link on the page. Tips: in your browser press F12, right-click a link in the Elements tab and choose Copy → Copy selector; the address can be in href or in another attribute such as data-pdf - if the scope names the attribute (as above) the tool reads that one.
  3. Click Find and analyze PDFs. The progress line shows how many sections have been opened and how many PDF links have been found so far; then the analysis starts by itself. Stop cancels a search that is still looking (it finishes the step in progress, usually a few seconds).

How collapsed sections are handled. The tool first reads the page's HTML. If the page has collapsed sections (a title you click to expand, an accordion, a <details> block) or shows no PDF links at all, it opens the page in a hidden browser and does what you would do: it clicks every collapsed section, waits for the content to load, and repeats until nothing new opens. Only the sections inside the scope are opened - with the example scope, Titles 2, 3, ... are never touched. Then the finished page is read with the same scope. For the CNMI Commonwealth Code, Title 1 alone opens 246 sections in about half a minute and yields 1,294 PDFs.

Pages whose content is in a frame (iframe). Some sites show everything inside an <iframe> (for example law.go.kr: the page itself is an empty shell and the list of attachments is inside the frame). The tool reads the frames too: a scope such as ul li a:nth-of-type(3) is applied to the page and to each frame inside it, and collapsed sections inside a frame are opened there. Links are resolved against the frame's own address, so relative links like flDownload.do?flSeq=... work. Two things help it recognise PDF links that have no .pdf in the address: if you give a scope, every link it selects is taken; if you give none, links that say they are a PDF (the word "PDF" in the text, a class, or an icon's description such as PDF파일 다운로드) are taken. A link with only an icon is named after its list item or table row (for example "[별표 1] 업무처리기간"). Titles in any language (Korean, Chinese, Arabic ...) are kept.

Pages that load their links late. Some pages (law.go.kr is one) sit idle for several seconds before their scripts ask for the list, so a page that looks "finished" may not be. When your scope has found nothing yet, the tool keeps waiting - up to 30 seconds (12 seconds when there is no scope) - for it to match, and then waits for the rest of the list. If it still matches nothing, the result says "The scope matched nothing, even after waiting 30 seconds". Frames on another website, frames inside frames, and srcdoc frames are read as well.

Example: only one title of a long list

On https://cnmilaw.gov/commonwealth-code the titles are the entries of the outline. To get only Title 9: Vehicle Code (269 PDFs), use the scope #cmctree>.tlist>li:nth-of-type(9) a[data-pdf*='.pdf'] - "the 9th title". A more robust way to write the same thing is by the title's own id, which does not change if titles are added: #cmctree>.tlist>li[data-id='7305'] a[data-pdf*='.pdf']. Only that title is opened (47 sections in about 20 seconds); the other titles are never touched.

Following links through several levels

Some sites need several steps: a list of departments, each with agencies, each with rules, each rule page holding the PDF. Click + Add a level under the scope, once per extra step. The scope of level 1 selects links to pages to open; on every one of those pages the scope of level 2 selects links; and so on - the links of the last level are the PDFs. Example (Colorado Code of Regulations):

  • Page: https://www.sos.state.co.us/CCR/NumericalDeptList.do; level 1 scope: tr:nth-of-type(170)~*:not(tr:nth-of-type(194)~*) a (the agencies of one department - 23 pages)
  • Level 2 scope: .rowEven td a (the rules listed on each agency page)
  • Level 3 scope: #application>>>>>>>>>table:nth-of-type(3) tr>td:nth-of-type(1) a:nth-of-type(1) (the PDF link on each rule page)

Each PDF in the results carries the titles of the links that led to it in Section Path (for example Mental Health Services > 2 CCR 501-1) and the page it was found on in Source Page. Maximum pages to open (Advanced, default 300) limits how many pages levels 2 and up may open. One browser is shared by all pages, and the tool waits between requests to the same site, so 60 pages take a few minutes. A page that cannot be read is skipped and reported; the crawl goes on.

Selectors copied from other tools. A run of > such as #application>>>>table is not valid CSS; it is read as "somewhere below" (an ordinary descendant), so the selector above works as written.

Links with no address of their own. A link such as <a href="javascript:void(0)" onclick="OpenRuleWindow('5421','2 CCR 501-1')"> has its address built by the page's script. When your scope selects such links, the tool clicks each of them in the browser and records the address the page tries to open (.../GenerateRulePdf.do?ruleVersionId=5421&fileName=...), without downloading anything there; the analysis that follows then fetches it and reports whether it is really a PDF. Addresses written out in the click handler (window.open('/files/a.pdf')) are read directly. Links that lead nowhere are counted in the notes.

Pages with their own crawler

Some pages are too particular for the generic search. When the address you type is one of them, a blue panel appears under the address saying "Recognised page", and a dedicated crawler is used (the scope and the other options below do not apply). Currently:

  • Superfinanciera - Circular Básica Jurídica (superfinanciera.gov.co/publicaciones/10115528/circular-basica-juridica-ce-00625/): its Partes, Títulos and Capítulos are inside an iframe that loads on demand. The tool opens each Capítulo in the browser and lists every attachment of every Capítulo (PDF, DOC/DOCX, XLS/XLSX, ...), with the path Parte > Título > Capítulo in Section Path, the real download address, the file type, and the site's own numbers in Site IDs. It never uses the "DESCARGAR" buttons and takes about 4 minutes per Parte (12 for all three).

Options of that panel: Only this Parte (faster), and Read the files. The attachment addresses only work inside the site's own session, so the normal analysis cannot fetch them. Without "Read the files" the rows are listed with status Unknown and the explanation, not as failures. With it, the tool downloads each attachment into memory, inside the same browser session (exactly what clicking it does; nothing is saved) and fills in file size, page count (PDF and DOCX), language and last modified date; .doc and .xls files give size and date but no page count.

Advanced options.

  • How to read the page - Automatic (recommended), Page HTML only (never uses the browser), or Always use the browser.
  • Maximum pages to open - for several levels: the most pages (levels 2 and up) that may be opened. Default 300, at most 1,500.
  • Maximum PDFs to analyse - default 3,000, at most 5,000. The Excel/dashboard limit is the same as for any other input.
  • Extra "click to open" selector - only needed if some sections are not opened by themselves (the tool already recognises aria-expanded buttons, <details>, and common tree and accordion toggles).
  • "Next page" button selector - for lists split over several pages, or "Load more" buttons: the tool clicks it again and again and merges what it finds, until it disappears or nothing changes (at most 30 pages).
  • Also take Word files - includes .doc and .docx.
  • Strict - keep only addresses that end in .pdf (or .doc/.docx). Off by default: a link that your scope selects is kept even when its address has no .pdf (many sites use addresses such as download.do?id=7), and the analysis then reports what each one really is - a link that is not a PDF shows up with another Content Type.
Needs Playwright. Opening collapsed sections uses a browser. Run pip install playwright once (it drives the Microsoft Edge or Google Chrome already installed - no browser is downloaded). Without it the tab still works for pages whose links are already in the HTML, and says so when it cannot open sections. The page's own requests are checked like every other request the tool makes: private and local addresses are refused, images, video and fonts are not loaded, and nothing is downloaded by the browser (the PDFs are fetched by the normal analysis).
Speed. The tool waits between requests to the same website (request: delay in config.yaml, 0.5 seconds), so 1,000 PDFs take roughly 15-25 minutes. You can leave the page; your search and results are kept (see "Your work stays when you switch tools").

What is checked for each URL

  1. Does it work? Redirects are followed and the final address is analysed.
  2. Is it a document? A direct PDF/DOC/DOCX is recognised from what the server sends back, not just from .pdf in the address.
  3. If it is a normal web page (a "landing page"), the page is searched for document links (links, frames, embeds and objects). Links are cleaned and de-duplicated. Links without .pdf in the address (for example /notice/123/pdf, /download?id=7, ?format=pdf) are also recognised from hints such as a pdf/download class, a download or type="application/pdf" attribute, "View PDF"/"Download" text or icons, or a citation_pdf_url / alternate-PDF declaration in the page. A hint is never trusted on its own: each candidate is requested and only counted if the server really returns a document (by its Content-Type or download file name).
    • NONE - no document link found.
    • SINGLE - exactly one document: it is opened automatically and its page count, language, last-modified date and size are reported.
    • MULTIPLE - more than one document: the number is reported and nothing is chosen for you. All the links are listed on the Document Links sheet of the export.

    Documents shown inside the page (iframe). Many pages display the PDF in a frame rather than linking to it. These count as the page's document: a frame pointing at a PDF, a PDF viewer wrapper (for example viewer.html?file=report.pdf, Google or Office viewers, Google Drive previews), a frame whose address has no .pdf but serves a document, and a frame that holds another page which contains the PDF (followed two levels deep). Buttons that open a file (a data-href or an onclick="window.open(...)" address) count like links. Video, social, ad and hidden frames are ignored.

    Frame and button together. When the page has both a viewer frame and a download link or button, the tool checks whether they lead to the same document (ignoring http/https, www., upper/lower case and #page= parts, and following redirects). Same document: reported as SINGLE. Different documents: reported as MULTIPLE. The Notes column says which case it was.

  4. Document details: page count, language (from the document text; Unknown if there is too little text, e.g. a scan), last modified (from the web server, otherwise from the PDF itself) and file size.

The tool is careful with websites: it waits between requests to the same site, retries after temporary errors with increasing delays, respects "too many requests" replies, and keeps going if one URL fails.

4. Base Templates

The Base Templates page (sidebar) shows the Base Template sheet of PDF Monitoring Templates.xlsx: one row per monitoring base template, with its created date, cached domain, whether it was added to Replit, the developer and comments.

Finding, adding and editing rows

  • Search looks in every column at once; type several words to narrow the list (all words must match). Added to Replit and Developer filter the list, and "(not set)" finds rows where that value is empty.
  • Click a column heading to sort; click again to reverse. Empty values always sort last.
  • Cached Domain is always stored as a plain lowercase hostname, exactly like the Domain column in the Daily Backlog and URL Analysis tools: https://WWW.Example.gov/path/ becomes www.example.gov. This happens when you type it and when you import. Several domains in one cell (separated by commas, semicolons or new lines) are tidied the same way and kept together; text that is not a web address is kept as written, and the import message tells you how many.
  • + Add template opens a form. Only the template name is required (no spaces). A new row appears at the top straight away, and the cards above the table update.
  • Edit and Delete are at the end of each row. Delete asks you to confirm and cannot be undone.
  • The page checks for changes every 15 seconds while it is open, so rows added by someone else using the same running tool appear by themselves and flash briefly.
  • Download Excel saves the rows you are currently looking at (search and filters applied) in the same column layout as the team's sheet.

Keeping it in step with the Excel sheet

The tool keeps its own copy of the table on your computer (data/base_templates.json, excluded from git). It cannot read the SharePoint file directly, so the sheet and the tool are brought together with Import Excel:

  1. Open PDF Monitoring Templates.xlsx in Excel or SharePoint and choose File → Download a Copy.
  2. On the Base Templates page click Import Excel and pick the file. The sheet called Base Template is found automatically, even if there are title rows above the headings.
  3. Leave Add only rows that are not here yet selected. Rows that are already in the tool are not duplicated and anything you edited in the tool is kept, so you can repeat this whenever new rows have been added to the sheet.
Replace the whole table makes the tool match the sheet exactly. Rows that exist only in the tool are lost; the previous table is saved as data/base_templates.bak (one step back).

5. Base Template Analysis

This page compares two datasets and tells you what is missing:

  • Dataset A - the URL analysis file you upload: Document ID, Domain, Spider Template and URL (the Excel file downloaded from URL Analysis works as it is, and so does any .xlsx / .csv with those columns).
  • Dataset B - the Base Templates page: Cached Domain and Monitoring Template. The current table is used every time you run the comparison, so rows you just added are included.

They are joined on domain: both sides are turned into a plain lowercase hostname first (https://WWW.Example.gov/a becomes www.example.gov), and a Base Template whose Cached Domain holds several domains is joined on each of them.

Step by step

  1. Either open Base Template Analysis in the sidebar and choose your file, or run an analysis on the URL Analysis page and click Send to Base Template Analysis - the rows arrive already compared (skip to step 4). On that page Compare again repeats the comparison with the latest Base Templates; the row numbers are positions in the URL Analysis results table.
  2. Check the column choices. The tool finds the URL, Spider Template, Domain and Document ID columns by their headings (even when title rows sit above them); change any that are wrong. URL and Spider Template are required; if there is no Domain column the domain is taken from the URL.
  3. Click Compare with Base Templates. The cards show how many documents need fixing; click a card to see just those rows.
  4. Work through the Books tab (one row per book, with its Row number in your file), the By Domain tab and the Base Templates tab (the other side of the join). See "Seeing everything by domain" below.
  5. Fix the problems at the source: correct your file, or use Add base template on a row to open the Base Templates form with the domain filled in. Then upload / compare again.

Seeing everything by domain

The By Domain tab lists every domain in your file with, for each one, how many books it has and how many of them are OK, Check (information flags only) and Needs fix, a colour bar showing that split, how many are missing a URL or a Spider Template, which Base Template(s) it was joined to, and a Status:

  • OK - every book of the domain is fine.
  • Check - nothing to fix, but some books only matched the Base Template after ignoring www..
  • Needs fix - the domain has a Base Template, but some of its books are missing a URL or Spider Template.
  • No Base Template - no Base Template has this domain as its Cached Domain.
  • No domain - books with no domain at all.

The cards at the top give the same numbers for the whole file: books in the file / to fix / to check / OK, and domains / OK / to check / with books to fix / with no Base Template. Click a card to filter the list to it, and click a domain to see its books. Domains with the most books to fix are listed first.

Selecting and downloading

  • Download All Data - the whole comparison: every book, every domain, every Base Template.
  • Tick rows (in the Books tab, or in the By Domain tab) and click Download Selected (N) - only those. Ticking a domain includes all of its books. Select all filtered ticks everything matching the current search and filters (across all pages); Clear selection empties it.
  • Books needing a fix only and Current filter are one-click shortcuts for the two most common selections.
  • A selected-data download is a complete report of just those books: its Review, Needs Fix, Domains, Base Templates Review and SUMMARY sheets are all recalculated for the selection, and the SUMMARY says how many of the total books it covers. Your ticks are kept while you visit other tools.

The report is not saved on the server - download it while the page is open (results are kept for two hours).

7. Command line

The same engine can be run without the web page.

Analyse the URLs in an Excel file

.\run.bat --input books.xlsx
.\run.bat --input books.xlsx --url-column "Source Link" --id-column "Document ID" --title-column "Book Title"
.\run.bat --input books.xlsx --fresh          # ignore cached results

The result is written to an output folder next to the input file (<name>_analyzed.xlsx); the input file is never changed.

Build the daily backlog workbook

.\run.bat daily-workflow --ui "StartPointStatus-01-Oct-2026.csv" --powerbi "Details Table.xlsx"

Attachments of the Superfinanciera "Circular Básica Jurídica" (Parte → Título → Capítulo)

The page superfinanciera.gov.co/publicaciones/10115528/circular-basica-juridica-ce-00625/ shows its content in an iframe that builds everything on demand, so it has its own crawler. It drives the real page in a browser (Playwright, using the installed Edge or Chrome):

python scripts\cbj_attachments.py --out output\cbj_attachments.xlsx
python scripts\cbj_attachments.py --parte 1 --max-capitulos 3 --headed     # a quick look, with the browser visible
python scripts\cbj_attachments.py --read-files                             # also read each file (in memory) for size, pages, date

The same crawler is built into Find PDFs on a Page (paste the page address there and its results appear in the normal dashboard); the script is for running it without the web page.

  • It opens every Parte, every Título and every Capítulo in the sidebar and lists all attachments of each Capítulo (PDF, DOC/DOCX, XLS/XLSX or anything else), with the file name, type and the real download address (.../apiCircularBasica/descargarAnexo/<id>). It never uses the "DESCARGAR" buttons.
  • It waits for conditions, not fixed delays: the clicked Capítulo must be the selected one and the site's own requests must have finished and stayed quiet.
  • Each attachment is found three ways and cross-checked: from the site's own attachment data, from the page and every iframe in it, and by clicking it and recording the request the page makes (that request is cancelled - nothing is downloaded). The Found In and Verified By Click columns show this.
  • A Capítulo that fails is retried (--retries, default 2), logged to logs\cbj_attachments.log, listed on the Errors sheet, and the crawl continues.
  • The workbook has the sheets Attachments (one row per Capítulo and file, with Parte / Título / Capítulo), Unique URLs (each URL once, with every place it appears), Capitulos, Errors and Summary; a .json copy is written next to it. The same file in two Capítulos has a row for each, so no hierarchy is lost.
  • The site's own menu lists "Título III. Sociedades comisionistas de bolsa de valores" twice under Parte III. Rows are told apart by the numbers the site itself uses (Site IDs, written Parte/Título/Capítulo): a repeated row with the same numbers is recorded on the Capitulos sheet as duplicate and not read or listed twice, while a repeated label with different numbers would be read as its own Título (marked Title Row # 2).
The download addresses only work inside the viewer's own session: requested directly they answer 401. They identify the files; to fetch them use the site's page, or ask for the crawler to be extended to save the files.

9. Troubleshooting

What you seeWhat to do
Red LOW MATCH box; Book Type list is short (e.g. only PDF and Unmatched)The CSV is a partial export or from another day. Upload the full StartPointStatus file for the same day as the Power BI file.
Book Types differ from what you expectedBook Type is the BookCategory from the CSV. Blank values show as Unknown; books missing from the CSV show as Unmatched. Neither is in the action lists.
The Excel report button stays greyIt takes about a minute for a large CSV. If a message appears instead, read it - for example a file open in Excel must be closed first.
Many URLs are BLOCKED (403/401/429)The website refuses automated requests; the address may still work in a browser. Try again later or with fewer URLs at once. This is a limit of the website, not of the tool.
Status BLOCKED with "Blocked by bot protection (Radware / Cloudflare...)"The site answered with a "verify you are a browser" page instead of the real page (the HTTP status can still be 200). The tool cannot see the page's links, so it deliberately does not say "No Document Link" - the Document Link Type is left empty. Open the page in a normal browser to check it. Best fix: click "Paste page source" on that row (or use the Page Source tab) and paste the page's HTML copied from your own browser. Alternatively tick Open blocked sites in a browser window and retry (a page that only shows a verification page works once you approve it in the window), or try browser.enabled: true in config.yaml (optional Playwright fallback) - it works on some sites but not all, and the tool does not try to defeat captchas. For sites you maintain or rely on regularly, ask the site owner to allow-list the tool.
HTTP 202 and the note "bot-protection page"The site returned a holding page instead of the real content. Open the address in a browser to confirm.
A result looks out of date and is marked "cached"Results are reused for one hour. Click Re-analyze for a live check.
"Document is larger than 50 MB"The file was not downloaded. Raise processing.max_pdf_bytes if you need page counts for big files.
Excel upload says it could not find the URL columnPick it from the Select URL Column list. Make sure the column really contains web addresses.
The page does not load, or shows old behaviour after an updateMake sure only one copy is running (close other terminal windows that ran run_dashboard.bat), then start it again. If port 8080 is busy, set PORT to another number.
"The report is no longer available"The tool was restarted, which clears the dashboard. Upload the files again.

10. Data and safety

  • Everything runs on your computer. Your files are not sent anywhere except that URL Analysis contacts the websites you ask it to check.
  • Uploaded files and generated reports are kept in the uploads and output folders inside the project, and the Base Templates table in data. They contain business data, so delete old ones when you are done. They are excluded from git.
  • Only http and https addresses are checked. Private, local and internal network addresses are refused, including when a website redirects to one.
  • Downloaded documents are read in memory as data only - they are never opened or run - and are not kept.
  • Pasted or uploaded text that starts with = is stored as plain text in the Excel files, so it cannot run as a formula.
